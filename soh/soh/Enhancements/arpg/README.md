# ARPG vertical slice

An adventure layer for Ship of Harkinian with Diablo-inspired combat and loot and an NPC quest campaign. Open **Dev Tools → ARPG Mod → Open ARPG Mod** to configure its subsystems, then load a save. The ARPG master switch, monster affixes, and Hyrule Reborn quests default to on; item modifiers and skills can be enabled separately. Randomizer saves also require **Allow ARPG in randomizer saves**.

## Hyrule Reborn quest campaign

The [40-quest campaign](QUEST_CAMPAIGN.md) follows the main story through eleven regional arcs. Approach an NPC with a gold **!**, then press **J** or choose **Start → Quests → Campaign quests**. Accept missions, track named hunts and collected supplies, rebuild persistent world sites, and return to the contact for XP, rupees, and a choice of gear. The native NPC conversation also offers **Local quests**, including acceptance, deliveries and reward choices. Completed sites provide places to rest. Use the journal's Save page to preserve progress.

## Fast manual testing

From the `soh` checkout, run `./soh.sh test`. This opens a separate, temporary adventure directly in Hyrule Field with the full debug inventory, level 20, a trained Swordmaster build, spare skill points, and all ARPG systems enabled. Intro, story/entrance/song cutscenes, and boss intros use SoH's built-in skip settings. The skill journal opens immediately; the loot inventory has four equipped rolls and twelve comparison items. **Settings & testing** opens the **Testing shortcuts** section, which provides health/magic refills, cooldown resets, skill points, boss-tier gear, single-enemy and pack spawning, pack cleanup, region travel, child/adult switching, and the debug scene selector. Test characters start fresh on each launch; test settings persist.

`./soh.sh run` opens the normal profile. The launcher's default profiles live under `~/Library/Application Support/shipofharkinian/profiles/`: `player1` contains ordinary saves, while `arpg-testing` holds testing settings. They survive a clean rebuild. Set `SHIP_HOME` to choose another normal profile or `SOH_PROFILE_ROOT` to relocate both defaults. The sandbox preset only runs with `SOH_ARPG_SANDBOX=1` on the temporary debug file; ordinary save slots are excluded.

## Play loop

Nearby villagers now support [voiced NPC conversations](../local-npc/README.md): talk normally to hear their original dialogue and continue into local topics in the same native textbox. **F7** starts a nearby conversation or opens question entry during local topics. Configure services and character voices under **Settings & testing → NPC dialogue**. The feature works independently of the ARPG master switch.

- Champions and Elites roll stat bonuses, resistances, immunities, and vulnerabilities. Colored floating labels identify their tier and affixes. Enemies also roll a fixed region level, HP, damage, and movement variation. Champion/Elite spawn rates are configurable. See [Regional enemy system](ENEMY_SYSTEM.md) for packs and tactics.
- Defeated enemies grant XP. Champions grant double XP and Elites quadruple XP. Levels award passive points up to level 50; every even level awards a technique point and each distinct boss awards two technique points per save. Repeated defeat callbacks for the same actor cannot pay twice.
- Enemies drop named equipment collectibles. Bosses guarantee gear; elites have a higher drop chance. Low-level ordinary enemies drop gear about 3% of the time. Item level follows the defeated enemy and scales the modifier roll. Walk into a drop to collect it; loot goes into a 48-slot backpack without replacing equipped gear. A full backpack leaves the collectible on the ground. Optional pickup textboxes use CustomMessageManager. Bonuses apply when the matching base item is equipped; switching base equipment makes that slot's modifiers inactive.
- The [skill system](SKILL_SYSTEM.md) has 37 skills across Sword, Magic, and Guardian, with connected prerequisites, 22 directed synergies, rank previews, and two optional rune variants for each of 18 active techniques. Basic sword damage scales with level. Basic hits build Momentum that strengthens the next sword technique.
- Press **K** for the skill journal. Configure six action slots, then cast with **1–6** or controller **D-pad Up/Right/Down/Left (1–4), L + D-pad Left/Right (5–6)**. Every technique has its own recharge timer on the action bar. Keyboard keys can be reassigned in the journal.

## Loot inventory

Press **I**, choose **Gear** in the journal, or press **Start**. With ARPG enabled, a single adventure journal owns the pause interface. The engine still prepares and tears down its normal pause state, but its old drawing and input handlers do not run behind the journal. Escape/controller Back returns from item details to the loadout or from another journal page to Gear; Escape again, Start, or **Resume** returns to play. Keyboard and controller navigation are enabled while the journal is open, and their previous settings are restored on close.

The journal pairs native OoT lettering, item-icon tabs, yellow selection brackets and an authored indigo stone tablet with readable Montserrat body copy. Quest rewards form a medallion ring around the Triforce, Spiritual Stones have a dedicated row, and songs show the original colored note and A/C-button symbols. Gear sits in bounded, rarity-colored slots; empty slots use matching outline symbols. Top tabs expose the main pages, with Save and Resume always available in the header. Bracket keys or controller LB/RB cycle pages. The six main pages fit one row at 1024 pixels; very narrow windows use a page chooser and full-width item inspector. Gear combines its worn slots and backpack with all 24 native usable-item slots, ammo, bottles and direct custom-item C-button assignment. Search/type filters, crafting, comparisons, character bonuses, native button swaps, elemental arrows and optional item cycling remain available. Other pages provide:

- **Quests:** the 40-quest Hyrule Reborn campaign, with a separate Quest items & songs view for native quest rewards, heart pieces, Skulltulas, character totals and the randomizer's collectible list. Learned songs show their notes and support native playback and ocarina practice using the keyboard, controller or held note buttons.
- **Map:** the original world image, discovery clouds, quest/trade destinations and Skulltula completion; in dungeons, discovered/map-unlocked floors, room palettes, compass-gated unopened chests and bosses, keys and map status. Mirrored-world rendering is preserved.
- **Save:** an explicit save confirmation through `Play_PerformSave`, including the ARPG save sections. Temporary debug adventures cannot overwrite a normal save slot.

The journal no longer hands **Quest & map** back to another menu. Disabling ARPG closes it through the engine's normal resume lifecycle. Native game-over screens remain separate.

The menu pairs a compact backpack grid with a loadout while retaining its OoT stone artwork, indigo palette, native message glyphs and yellow selection cursors. Gear, Gems and Runes have separate stash tabs; gems show all three grades together. Sword, shield, tunic and boots share one row above the usable-item grid. Selecting gear opens its inspector alongside the backpack, with equip and C-button actions above the stat comparison. ## Forge, uniques and sets

New Unique-quality drops resolve to eight named uniques or a piece of one of three four-piece sets. The identities, ordered sockets and material satchel were introduced in version 6 and remain in version 7. Earlier saves retain their existing gear and rolls unchanged; old unnamed Unique items remain valid. `LootCatalog.h` is the shared, append-only catalog for generation, combat queries and inspection. Adding a definition does not require duplicating its powers in the UI.

- **Cinderwake**, **Moonwell Fang**, **Briar Oath**, **Dawnglass**, **Ashen Pilgrim**, **Veil of the Deep**, **Wayfarer's Promise** and **Redstep** have fixed modifier combinations and distinct technique-damage, recharge, magic-on-hit or life-on-kill properties. Technique damage affects damaging techniques, not healing or invulnerability. Recharge reduction is capped at 40%, technique damage at +100%, magic recovery at four per basic-hit window, and life on kill at one heart.
- **Briarwatch**, **Cinderbound** and **Tidecaller** grant bonuses at two and four matching, actively worn pieces. Native equipment changes can deactivate a piece; the full-set effect disappears immediately. Comparison includes crossing set thresholds, socket bonuses and runeworks.
- Enemies can drop physical gems and rune stones separately from gear. The satchel stores up to 999 of each ingredient without using backpack spaces. Full stacks leave their collectible on the ground. Higher regions unlock better gem grades and Lux/Umbra runes.
- Six gem families have Rough, Cut and Perfect grades. Eighteen separate painted icons distinguish ruby's broad hexagon, sapphire's teardrop, topaz's triangle, emerald's stepped rectangle, amethyst's pointed oval and diamond's round brilliant. Rough stones retain chipped mineral surfaces; Cut stones have clean, broad facets; Perfect stones have intricate cuts and brighter reflections. Grade buttons preview the selected family, refinement shows larger before/after artwork, and depleted stacks dim. Their bonuses depend on the equipment slot. Three gems combine into one of the next grade. [Gem art prompts](../../../../art/gem-icon-prompts.json) record the individual transparent-image generations.
- **I → Forge** opens a full-page workbench with a backpack picker, enlarged gear and socket preview, and separate Insert stone, Add socket, Extract, Refine gems, Runeworks and Salvage actions. Colored gem icons and engraved rune tablets show stack counts; each action displays its result and cost. Narrow windows use a separate gear picker, collapsible action and recipe choosers, and a scrolling workbench. The forge owns the journal page; Back to equipment or Escape returns to the main navigation. Crafting works on selected backpack gear. Salvage unwanted, empty-socket gear for essence; add sockets; insert stones into the next empty socket; or spend eight essence to extract and recover every stone. Extraction checks all destination stacks before charging anything. Salvage requires a second click and cannot destroy socketed stones.
- Eight ordered runeworks—**Kindling**, **Stillwater**, **Waywind**, **Bulwark**, **Sunbreaker**, **Nightwell**, **Oathkeeper**, and **Stormpath**—require a common item of the listed slot with exactly the recipe's socket count. The Runeworks page pairs a recipe list with ordered rune icons and actual bonuses; selecting a rune or Prepare these runes opens the insertion workbench. Wrong order, extra sockets, gems, or non-common quality do not activate a recipe. Empty common bases support up to three sockets from item level 24; ordinary lower-level bases and magic/rare gear support two, and unique/set gear one. Socket count cannot be changed while stones are inserted.

The temporary adventure's **Forge test kit** adds sample bases, all uniques and sets where backpack capacity allows, plus ingredients. `SOH_ARPG_FORGE_PREVIEW=1 ./soh.sh test` prepares that kit automatically. It has no effect on normal saves. Crafting uses portable atomic transaction rules; mutations are enabled only during normal control or the initialized pause screen.

## Implemented effects

Gear supports melee/ranged damage, critical chance, elemental procs, percentage armor, movement speed, loot chance, magic discounts, and temporary heart capacity. Vitality respects the vanilla 20-heart ceiling and records only the added capacity, so disabling gear or switching equipment preserves earned hearts. Armor and Toughness add percentage reduction, capped at 25%; positive hits always retain at least one health unit. **Tuning (dev)** exposes spawn rates, Champion share, XP/drop rates, and minimum/maximum power per modifier and rarity. Roll ranges are multiplied by the new item’s level factor; changes affect future drops, and each range can be restored to its default.

Sword techniques include sweeping Cleave, crossing cuts, Cyclone, safe forward thrust, orbiting blades, Execution, ground shockwaves, and piercing beams. Magic adds fire, frost/chill, chain lightning, delayed meteors, protection, infusion, cost reduction, regeneration, and recall. Guardian offers Evasion, healing and mitigation through Rallying Cry, Riposte counters, Second Wind, and defensive/loot passives. All technique details and base cooldowns are in [Skill combat and progression](SKILL_SYSTEM.md).

Active casts validate player control, rank, position, resources, and cooldown. Sword techniques need no magic. Magical casts use the native meter state machine. Pattern effects pair native player-aligned colliders with feathered sword trails and the original animated dust, flame, lightning and flash textures. Physical strikes use restrained pale steel trails; elemental casts use small readable accents. `NativeEffects.h` shares that palette and render state across skills, auras, arsenal strikes, relic procs, boss warnings and world interaction markers, preserving enemy damage tables and native reactions. A collision gate rejects walls and repeated contacts against the same enemy in one strike. Holy Aura and Wind Recall use their native utility spell actors.

## Architecture and persistence

`ARPGTypes.h` contains the C-compatible POD save data embedded in `SaveContext.ship.arpg`. `ARPGSave.cpp` registers the versioned `arpg` section at startup. Saving reads the SaveManager worker's immutable `SaveContext` snapshot. Version 6 adds item identities, ordered sockets and material counts. Version 5 adds character-specific action slots, rune choices, and one-time skill migration. Version 4 added item level; older rolls keep their existing powers and display as legacy items. Version 3 added fixed backpack slots; versions 1 and 2 retain their equipped gear and gain an empty backpack. The codec accepts legacy data and validates indices, arrays, powers, points, and XP before narrowing values. Saves without an ARPG section initialize cleanly.

The seed and integer PRNG state are both persisted. The same starting state and call order produce the same rolls across platforms; saving and loading continue the stream. Deterministic co-op replication landed 2026-10-12: the room owner publishes an `arpgSeed` via `UPDATE_ROOM_STATE` (Anchor admin menu → **ARPG Co-op → Share Elite Rolls**), and every connected client derives Champion/Elite tiers, regional stats, affix sets, and elite names from `hash(seed, scene, actorId, params, occurrence)` instead of the personal stream (`CoopRules.h`), so both worlds roll identical elites with zero extra traffic. Loot intentionally stays on the personal stream — drops remain instanced per player like Diablo II personal loot. `ARPG_ENEMY_KILL` is a team-relayed packet (go-anchor `teamExcept`, no queueing) that grants party members half the rolled XP with their own XP-rate applied; Champion+ slays also surface a notification. Scene-spawned enemies are fully deterministic; dynamically spawned actors (e.g. Stalchildren rising at night) key off init-order occurrence counts, which can drift a single occurrence index between clients in rare timing cases — elite identity stays stable per occurrence.

`OnDamageActor` carries the target, source actor, damage flags, attacker alignment, and mutable damage. Player bonuses apply only to player-aligned attacks against enemies. Enemy affixes can scale outgoing damage separately. Hard collisions and zero-damage vanilla hits do not consume offensive rolls. The engine damage accumulator clamps ARPG damage to its byte range.

EnemyDifficulty supplies the shared enemy/curated predicates and HP helper. King Dodongo's private HP uses the native struct instead of a hardcoded N64 offset. Movement scales freshly calculated horizontal velocity, leaving AI speed state unchanged; combined curated-enemy movement is capped at 2.25×. ObjectExtension's existing actor teardown frees affix, reward, spell, and loot records.

## Scope and remaining playtesting

- King Dodongo, Phantom Ganon, Ganondorf, and Ganon receive outgoing-damage/movement affixes only. Their manual damage/HP paths do not consistently use the generic collision pipeline. Other bosses and multipart enemies still need encounter-specific balance and compatibility testing.
- Swift affects actors using the standard horizontal movement helper. It does not accelerate every animation or custom movement implementation. Frail amplifies damage; Spellwoven resists magic as a group.
- Rolls without a modifier appearance use the remastered ordinary base model; labels identify the exact base. Custom player skeletons and remote Anchor actors retain their own equipment rendering. The worn clothing uses native body geometry with new color and attached ornaments. A custom sword paired with a native shield retains the native combined shield/scabbard mesh plus the new hilt. Child sizing is supported, but all animation/base combinations and the native pause model still need broader visual acceptance.
- Enabling affixes configures new and existing living enemies. Disabling removes live HP scaling and labels; disabling packs removes their generated actors. Regional-stat changes preserve the fraction of health already lost.
- Infusion uses a small elemental hand glow and drifting motes. Guardian and utility skills use subtle trails, dust and rising motes, including child-scale variants. Bespoke weapon shaders and a shared stash are not implemented. This is a first playable slice, not a completed encounter balance pass.

## Development and QA

From the `soh` checkout:

```sh
./soh.sh build
cmake -S tests/arpg -B /tmp/soh-arpg-tests -G Ninja -DCMAKE_BUILD_TYPE=Debug
cmake --build /tmp/soh-arpg-tests
ctest --test-dir /tmp/soh-arpg-tests --output-on-failure
```

Console commands:

```text
arpg
arpg window
arpg inventory
arpg give <tier 1=champion 2=elite 3=boss> [slot 0=sword 1=shield 2=tunic 3=boots]
arpg level <1..50>
arpg points <passive|active> <amount>
arpg cast <skill ID>
arpg reroll
```

The legacy `arpggive`, `arpglevel`, `arpgpoints`, and `arpgreroll` aliases remain available. Mutating commands require an enabled ARPG save. `reroll` resets the RNG stream for future rolls; it does not alter existing actors or gear.

The optional `SOH_ARPG_RUNTIME_TESTS` CMake option includes three runtime integration harnesses, all restricted to an isolated `SHIP_HOME` whose directory name begins with `soh-arpg-qa-`. `SOH_ARPG_QA=1` runs the gear/enemy regression suite and writes `runtime-results.json`. `SOH_ARPG_SKILLS_QA=1` runs the skill suite and writes `skills-runtime-results.json`: every active/rune combination, native collisions, duplicate-hit rejection, overlapping cooldowns, consecutive magic transactions, exact discounted costs, Momentum, actual pack combat, and saved loadouts. Each creates a debug adventure and writes/reloads slot 1 only in its isolated home. Never point either at an ordinary save directory. The build option defaults to off. Add `SOH_ARPG_AURA_QA=1` to the skill harness for focused aura lifecycle checks instead of the long cast sweep; it writes `auras-runtime-results.json` and checks the visual actor cap, passive healing effect, pause/resume, respec, scene change, child rendering, expiration and master-off.

The portable suite covers save roundtrips and snapshots, legacy/malformed data, seeded RNG continuation, XP/level caps, damage bounds, 30,000 distinct-modifier selections, full-backpack swaps, overflow rejection, item conservation, and backpack migration/roundtrips. The runtime harness covers native spell spawns and enemy damage tables, adult/child transitions, physical loot rendering and pickup, gear and master toggles, temporary heart capacity, Farore's Wind recall, asynchronous SaveManager save/reload, per-boss active-point limits, roll-range tuning, and EnemyDifficulty HP/full modes.

## Waystone expeditions

Open **Expeditions** in the equipment journal while in a wilderness region. Select a gear slot, begin a run, and choose one of three seeded oaths. Resume to face a warband, a champion pack, then a warden and guards. Each wave requires all of its registered enemies to be defeated. Clearing a depth offers one targeted equipment cache, rune cache, or gem cache; every third depth offers unique/set equipment. Claim a cache before continuing into the next depth, or end the run and keep previously claimed loot.

Five oath definitions live in `ExpeditionRules.h`: armor with ranged/explosive counters, fast fragile hunters, and fire/frost/storm enchantments. Enemy endurance and damage increase with depth independently of the level-50 item ceiling. Damage scaling has numerical safety limits; this first encounter loop still needs extended balance playthroughs and more objectives/enemy families before it represents a finished endgame.

The waystone is an original scene-lit mesh with carved uprights, bronze inlays, and a suspended crystal. It turns gold when the cache is ready. It is a visual landmark, without blocking collision. The current encounter roster retains the native enemy rigs and meshes.

Runtime rules:

- Solo wilderness only; protected settlements, dungeons and boss arenas reject expedition starts. Items, affixes, regional enemies and elemental enchantments must be enabled.
- Ambient packs pause for the duration of a run. Expedition waves work with ambient packs disabled and respect the live actor cap and ground/line-of-sight checks. Incomplete spawns are removed; unsafe placement waits for open space.
- Leaving the scene or moving more than 1,500 game units from the waystone during combat ends the attempt. Death or disabling required systems cleans up enemies. Claimed items and lifetime records remain.
- Only registered wave members advance progress. Duplicate callbacks do nothing; missing/despawned actors retry their wave without a clear.
- Reward transfers are atomic. A full backpack or capped material stack retains the complete unclaimed cache. A second claim is rejected.
- Save section version 7 retains existing versions 1–6, the expedition seed, depth, selected gear target, records, and earned cache phase. Reloading combat retries the same depth with the same route offers; actor references never enter save data. Earned caches survive reload and region changes.

`expedition_test.cpp` covers 10,000 seeds, all oaths/gear targets/catalog identities, full-stack transactions, interruption recovery, overflow limits and both 5,440-triangle waystone states. `expedition_runtime_test.cpp` is opt-in through `SOH_ARPG_RUNTIME_TESTS` plus `SOH_ARPG_EXPEDITIONS_QA=1` and an isolated `SHIP_HOME` whose basename begins with `soh-arpg-qa-`. It exercises actual spawned actors, tactics, damage integration, three-wave completion, SaveManager persistence, claiming, continuation, despawn recovery, feature gates, death, arena exit and scene cleanup.

### Campaign quests in a party

All 58 campaign quests support opt-in sharing through **Quests > My quests > Share quest with party**. Teammates use **Quests > Party > Join quest / Catch up**. Invitations explain age, story and preceding-quest requirements. The party board shows the common objective counts, a progress bar, members, reward claims and each player's reward value. Completed quests are collapsed by default. Sharing options let a player keep a quest and continue solo.

Shared hunt/recovery counts grow by half the base target (rounded up) per additional participant, up to eight participants: a four-kill hunt becomes six for two players and eight for three. Combat bounties grant 25% more personal XP/rupees per additional participant; gear remains personal. The largest joined party size is saved and does not shrink on disconnect. Once reward claims begin, the relay freezes that contract's size. Named quest packs keep their three persistent member identities and gain a health floor of `1 + 0.5 * extra participants`, without multiplying an already stronger room difficulty setting a second time.

The updated `mp-server` relay owns the common quest record. Build it from that directory with `go build -o go-anchor .`, then run `./go-anchor -port 43383`. The game negotiates quest protocol 1; older relays leave sharing disabled with an explanation. Native item/flag synchronization and the elite-roll seed are independent of quest sharing. Different teams and randomizer seeds have separate records. Each player accepts invitations and claims their own reward at the NPC; shared packets cannot grant gear, XP or rupees directly.

Hunts, recovery drops, gathering, restoration, visits, named packs, songs, deliveries, surveys, continuous vigils and story milestones share progress. Continuous vigils publish completion rather than pooling partial watches. Quest sites use the relay's first accepted position, and duplicate node events do not count twice. Contributions sent while an invitation is being acknowledged remain in the same ordered stream as the join request. Reconnects merge saved progress, restore shared sites, and never reopen claimed rewards. Room state is held in memory; when the room/server restarts, saved participating players repopulate it on reconnect. Normal saving is still required.

The protocol synchronizes quest identities, spawn sites, difficulty and completion. Enemy movement and ordinary combat simulation continue to use Anchor's existing behavior. This is not a new authoritative combat server.

Validation lives in `tests/arpg/quest-party/`: native two-client fixtures, portable rules/save tests, and real TCP relay tests. `SOH_ARPG_QUEST_PARTY_TESTS` is OFF by default; the isolated runtime harness requires `SOH_ARPG_QUEST_PARTY_ROLE=A/B` and a `SHIP_HOME` named `soh-arpg-qa-party-*`. The portable `arpg_quest_party_catalog` test checks the embedded relay catalog against the game's quest definitions. Regenerate it with the `arpg_quest_party_catalog` executable when definitions change.
